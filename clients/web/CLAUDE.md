# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`clients/web/` is a TanStack Start application — React 19, TypeScript, file-based routing — scaffolded with `create-tsrouter-app`. It implements the money-bae bill-cycle budgeting UI (sign-in, home dashboard, ledger, bills, income, PTO/holidays, settings) from the Claude Design mockup ("Money-bae UI mockups" project, `Money-Bae.dc.html`).

## Commands

Run from `clients/web/`:

- `npm run dev` — start the dev server (port 3000)
- `npm run build` — production build
- `npm run preview` — preview the production build
- `npm run generate-routes` — regenerate `src/routeTree.gen.ts` from the files in `src/routes`
- `npm run lint` — ESLint (`@tanstack/eslint-config`)
- `npm run format` — Prettier write, then `eslint --fix`
- `npm run check` — Prettier check only (no write)

No test suite is configured yet.

## Architecture

- **Routing**: TanStack Router file-based routing. `src/routes/__root.tsx` is the shared root (imports `styles.css`, wraps everything in `AppStoreProvider`, renders `<Outlet />` plus the TanStack devtools panel). `src/routes/login.tsx` is standalone (no app chrome). `src/routes/_app.tsx` is a pathless layout route — its component (`AppShell`) guards on `authed`, renders the sidebar/footer, and binds the h/i/b/l/p/s keyboard shortcuts; every other screen (`_app.index.tsx` = `/`, `_app.ledger.index.tsx`, `_app.ledger.$periodId.tsx`, `_app.bills.tsx`, `_app.income.tsx`, `_app.pto.index.tsx`, `_app.pto.$year.tsx`, `_app.settings.tsx`) nests under it. `src/routeTree.gen.ts` is auto-generated by the router plugin (during `dev`/`build`, or via `generate-routes`) — never hand-edit it.
- **Entry point**: `src/router.tsx` builds the router instance from the generated route tree; `src/main.tsx` mounts it into the DOM.
- **State/data layer** (`src/data/`): `api.ts` calls the real `servers/api` backend for Income/Bill/Ledger/LedgerBill/Pto/PtoPlan/HolidayHour (money fields as `{amount, currency}` via `dinero.js`, converted with `toMoney`/`toRawMoney`/`moneyToNumber`/`numberToMoney`). `store.tsx` (`AppStoreProvider`/`useAppStore`, a plain React Context + `useState`, no external state library) holds the flat top-level lists (`income`, `bills`, `ledgers`, `ptos`), loaded once on mount; nested resources scoped to one parent (a ledger's bills/incomes, a PTO year's plans/holidays) are fetched route-locally via `getLedger`/`getPto` instead. `mockData.ts`/`selectors.ts` now hold only the remaining decorative home-page content (`nextUp`, `sparkSeries`) that has no backing endpoint yet.
- **Styling**: a hybrid. Tailwind CSS v4 (`@tailwindcss/vite`) supplies one-off layout utilities (flex/grid/spacing) directly in JSX. The component _look_ — buttons, cards, tables, tags, dialogs, form controls — comes from the Nocturne design system ported from the mockup as plain CSS driven by custom properties: `src/styles/tokens.css` (palette/spacing/shadow tokens) and `src/styles/components.css` (`.btn`, `.card`, `.table`, `.field`/`.input`, `.tag`, `.dialog`, `.seg`, `.radio`, `.nav`, plus the app's `.mono`/`.mb-nav`/`.mb-row`/mascot-animation classes). Both are imported in `src/styles.css` after Tailwind. Use the Nocturne classes for a component's look; reach for Tailwind only for the surrounding layout.
- **Path aliases**: both `#/*` and `@/*` resolve to `src/*` (see `tsconfig.json` and the `imports` field in `package.json`) — either prefix works for internal imports.
- **Build tooling**: Vite (`vite.config.ts`), composing the TanStack Router plugin (`autoCodeSplitting` on), TanStack devtools plugin, Tailwind plugin, and the React plugin.
